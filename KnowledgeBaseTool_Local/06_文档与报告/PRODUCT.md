# KnowBase Hub 产品文档

## 这份文档解决什么问题

KnowBase Hub（8085）是内部知识库与机型矩阵工作台。本文面向知识库运营、产品资料维护和质量复核人员，说明当前可用功能、操作边界和最近一次全量验证结果。

## 产品目标

系统把知识内容、产品型号、治理召回、质量检测和修改审计放在同一个工作台中。所有写操作都应有明确确认、可回读结果和审计记录；高风险差异交给人工复核，默认安全项保持低成本处理。

## 功能清单

| 模块 | 主要能力 | 入口与结果 |
| --- | --- | --- |
| 知识库管理 | 分页查询、筛选、编辑、批量编辑、标签、查重、导入导出、详情查看 | `知识库`页；保存后返回审计回执 |
| 机型矩阵 | 型号检索、单元格编辑、批量编辑、产品目录、克隆差异识别、提交与幂等保护 | `机型矩阵`页；提交前显示差异和影响 |
| 智能映射 | 自动候选、手工换一条、展开证据、采纳/跳过、批次提交 | `智能映射`页；候选状态可追踪 |
| 知识图谱 | 关系复核、候选批次、主题校对、影响分析、候选回退 | `知识图谱`页；候选写入默认为待复核 |
| 参数校对 | 当前知识扫描、历史批次、AI 候选采纳/修正/误报、证据详情 | `参数校对`页；保留扫描和复核状态 |
| 知识库治理 | 月份范围、召回/有效召回筛选、周期加权大盘、导入导出、单条和批量删除 | `治理`页；批量删除需要勾选并二次确认 |
| 质量控制中心 | 任务池、任务导入、批次提交/忽略、任务编辑和状态统计 | `质量控制`页；状态在任务池中回读 |
| 修改与归档 | 修改记录筛选、详情、复制、归档批次查看/导出/删除、活动归档 | `修改记录`和`归档`页；保留来源与操作元数据 |
| 设置与操作库 | AI 配置、评分配置、APP/产品操作库、同步和健康状态 | `数据设置`页；保存结果通过接口回读 |

## 关键操作边界

1. 机型矩阵提交前必须通过差异校验；重复 `operation_id` 不得重复写入。
2. 产品目录删除或变更可能影响矩阵行列，接口会先返回影响预览并要求确认。
3. 治理批量删除只作用于当前月份范围和已勾选的 WikiID，不删除知识正文。
4. 来源筛选按完整来源标签或已登记来源代码匹配，不能使用会造成串项的子串匹配。
5. 测试和演练应使用系统临时目录 SQLite；正式 `instance/data.db` 由运行中的服务独占。

## 本次修复

- 来源过滤从子串匹配改为完整标签或显式来源代码匹配，避免“知识库内容检测工具”被归入“知识库管理”。
- 治理表增加当前页全选、逐行选择和批量删除确认流程，调用 `/api/governance/delete_items`。
- 增加 `closeKBDetailModal()`，修复知识库详情弹窗关闭按钮。
- 列宽拖拽和拖拽滚动使用 `requestAnimationFrame` 合并高频事件，减少 Chrome 布局写入次数。
- 矩阵配置单元格改为表体事件委托，避免为数千个单元格分别挂载点击处理器。
- 矩阵默认分页调整为 20 行（仍可切换到 10/50 行），并为表格行启用 Chrome 可视区域绘制隔离，降低宽矩阵切页和滚动时的主线程压力。
- 导航切换只更新上一个和当前视图/按钮，避免每次点击遍历全部模块控件。
- 启用滚动性能样式：关闭全局平滑滚动，隔离表格布局与绘制，降低大表格滚动时的重排压力。

## Chrome 卡顿复测（2026-08-26）

- 登录后的知识库首页默认 50 行，约 5,944 个 DOM 节点、1,000 个表格单元格；切换到矩阵页使用 20 行默认分页后约 11,636 个节点、2,560 个配置单元格。
- 50 行矩阵会产生约 6,400 个配置单元格、19,706 个节点，仍保留为手动选择项，适合需要批量查看的场景。
- Chrome 运行态连续切换“知识库管理”和“数据设置”时，稳定状态点击耗时约 0.3～0.6 秒；矩阵首次加载包含接口请求和表格生成，耗时高于纯导航。
- 复测页面控制台没有新增 `error` 或 `warn` 日志；主导航和矩阵筛选入口可正常工作。

## 已知风险与后续工作

- 页面未提供 `favicon.ico`，浏览器会产生一次 `404`，不影响业务功能。
- `test_prefetch.html` 中失效的 `../优化清单` 链接已删除；该测试页不是主应用运行依赖。
- 全量 HTTP 测试中 3 个失败需要同步更新测试夹具：为本地 PostgreSQL 准备测试知识记录，并按当前产品目录确认契约补充请求字段。
- pytest 运行期间必须停止或隔离 8085 正式服务，才能让 SQLite 指纹保护器返回成功退出码。

## 使用前检查

1. 启动服务后打开 `http://127.0.0.1:8085/`，确认登录成功。
2. 先在目标模块执行查询，确认数据范围和月份/型号筛选条件。
3. 所有删除、矩阵提交和候选写入操作都阅读影响预览后再确认。
4. 出现接口错误时保留页面提示、服务日志和 `operation_id`，再进行重试。
